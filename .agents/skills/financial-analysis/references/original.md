# 财务分析 Skill（v4.0）

## 这个 skill 要做什么

报表是结果，生意是原因。**好的财务分析是从结果倒推原因，再用原因推未来。** 算比率只是手段，不是产出。

报告写完要做到六件事：读完知道这家公司会不会出事、账实不实；读完能复述这家公司怎么赚钱；每个数字都在回答一个具体问题；找到了数字和说法对不上的地方；分清了什么会持续、什么是偶然；给出了能被推翻的判断。

**最关键的一条规矩：先看数字，后看说法。** 先不读任何公司介绍和管理层讲话，先把偿债、流动性、资产质量查一遍，再从数字推出这是什么生意；然后再读 10-K 和市场观点，看哪里对不上。多数平庸的分析，都是先信了公司讲的故事，再去找数字凑。把顺序倒过来，就是为了堵这个。

---

## 角色与边界

本模块是档案里的 `02_财务分析.md`，不依赖其他模块。下游从它拿东西：`03_商业模式` 拿"说法和数字的对照表"和业务判断去验证；`06_财务预测` 拿历史基线直接当假设表的历史列，拿财务安全定融资和利息假设；`04_战略决策` 拿资本配置台账看钱真花在哪，拿财务安全看战略有没有钱执行；估值模块拿财务安全定折现率和情景权重。

**做**：查清会不会出事、账实不实；从数字得出业务判断，标明这是判断，交给下游去验证。
**不做**：估值、投资建议、评价花钱方式对股东好不好（那是治理模块的事）、预判战略转向（那是 04 的事）。

## 数据从哪来

**数字只从底稿取，不自己上网搜。** 搜来的数字经过几手转载、GAAP 和 non-GAAP 混在一起、事后查不到出处。**底稿已经算好的（TTM、勾稽、资本配置合计）直接用，不重算**——脚本管取数和算术，skill 管解读。

| 来源 | 拿什么 |
| :-- | :-- |
| 财务底稿 · 美股 `{公司目录}/{WIKI} Wiki/raw/财务数据/EDGAR/financials.json`（`fetch_edgar_financials.py` 生成；**能不能用看 `meta.capabilities` 字段清单，不看 `script_version`**，判法见下）；A股港股 `raw/财务数据/*.xlsx` | 三张表、TTM、股本、租赁、资本配置台账、勾稽结果。**每个数从哪个字段取，按 `references/data-contract.md`**，不要自己猜字段 |
| `raw/` 原始文件（10-K / 10-Q / 年报）的**财务报表附注**（Item 8） | 底稿里没有的：分部数据、带维度的收入拆分、租赁明细、商誉减值原因、税务离散项、一次性损益的性质、应收构成、口径变更；**第 1 步体检要的**：债务到期表、利率结构、契约、信贷额度、担保或有、商誉 headroom、应收账龄与坏账、存货构成与跌价、资本化研发 |
| `raw/` 的业务介绍（Item 1）、管理层讨论（Item 7）、8-K 经营指标、月度销售公告、电话会 | **第 3 步才准读**。8-K 和月度公告往往比 10-Q 新一个季度，第 3 步必须看 |
| 联网 | 只用来补"最新一期财报还没进底稿"的缺口，标"待核实"；第 3 步查市场观点 |

被编排调用时，按派发 prompt 给的路径读。报告开头写明 `meta.fetched_at`（取数日）和 `ttm.period_end`（数据新到哪天）。

**底稿没有或过期**（`meta.fetched_at` 早于最近一期已发布的财报）：被编排调用 → 停下来报缺，由编排层跑 `_system/scripts/fetch_edgar_financials.py` 补；用户单独调用 → 自己跑一次脚本，报告开头写明"底稿为本次现取（YYYY-MM-DD）"。

**底稿能力校验（第 0 步先做，一次判完，别比版本号）：**

版本号是人手敲的常量，改功能忘了改号是常事（2026-08-28 实测：脚本功能已到 v0.4.0，`meta` 里还写着 0.3.0）。**只信脚本自己产出的字段清单：**

| 看哪个 | 说明什么 | 怎么办 |
| :-- | :-- | :-- |
| 需要的指标**不在** `meta.capabilities` 里 | 脚本压根不会找这一项 = 真的该升级脚本 | 报告 F7 记数据缺口，写明"脚本不支持 {字段}，建议扩 METRICS"；相关比率不算 |
| 在 `capabilities`、也在 `meta.missing_metrics` 里 | 脚本找了、这家公司没披露 | 按下面规矩 2 逐条判（真没有 / 在附注里），**绝不当 0** |
| 在 `meta.suspect_metrics` 里 | 命中的 tag 全是 XBRL 的 `Other*` 残差科目，取到的是"其他 XX"一小项，不是全额 | **不许直接用**。回 `raw/` 原文取该科目全额，正文标注"底稿标签失真，已按原文重填"，F7 建议改 `tag_map` |

`suspect_metrics` 是硬约束，不是提示。实测踩过两次：`cost_of_revenue` 只命中 `OtherCostOfOperatingRevenue`（导致毛利率显示成 92%）、`accrued_liabilities` 只命中 `OtherLiabilitiesCurrent`（10.9 亿的应计费用只取到 290 万）。被编排调用时派发 prompt 里会转写这份清单，但**以底稿里的 `meta.suspect_metrics` 为准**。

**读底稿四条规矩：**
1. `checks`（勾稽自检）有没通过的项 → 写进 F1"口径与局限"，说明差多少、为什么。"收入−成本≠毛利"没过，通常是公司的毛利标签口径特殊（如不含会员费），要在正文说明用的是哪个口径。
2. `meta.missing_metrics`（没取到的指标）**绝不能当 0 用**。"没这一项"和"这一项是零"是两回事。逐条判断：公司确实没有（写"不适用"）／脚本没覆盖到（记为数据缺口，相关比率不算）／是附注里的项目（去 raw 读原文）。
3. `ttm.notes` 说"缺去年同期"的指标，TTM 填 n/a，不拿单季拼。
4. 底稿和原文冲突 → 以原文为准，正文标注，并建议重跑取数脚本。

**数据要求**：最少 5 个完整财年 + 最新 TTM（近 12 个月）。基线表和资本配置台账都要 5 年；增速要 6 年数据才能填满 5 列。不够就在 F1 写明，缺的格填 `n/a`，不许拿短期数据冒充。

**预算**：≤40 次工具调用。主表数字底稿里都有，预算要花在读附注（债务、商誉、应收、存货、租赁）、核口径、对照说法上；花在找三张表基础数字上的调用都是浪费。大致分配：第 0 步 ≤6（含跑一次 render_tables.py）、第 1 步 ≤12、第 2 步 ≤4、第 3 步 ≤12、其余 ≤6。

## 第 0 步：口径与数据底座（算任何东西之前）

这一步做三件事，产出正文第一节。后面所有步骤引用的数字都以这一节为准，读者核任何判断都回这里对。

**0a 口径核对（≤10 行）。** 统计口径变了，趋势就是假的。逐项核对：会计准则变更、分部重新划分、并购从哪年开始并表、剥离或终止经营有没有追溯调整、财年区间有没有变（含 53 周年）、报告币种和汇率、GAAP 还是 non-GAAP。口径变了 → 要么按可比口径重算，要么在所有受影响的格子标 `*`，不许把不可比的数连成趋势线。non-GAAP 可以引用，但要写明剔除了什么，不能当事实基础。**TTM 单独一列，不参与"方向"判断**——它和最近财年重叠 6–9 个月，拿来判方向必然失真。

**0b 数据底座（≤10 KB）。** 把这家公司五年长什么样摆出来：精简三张表（利润表、资产负债表、现金流量表各十来行）+ 关键比率速览 + 一次性项目标注 + 体检补充表（流动性、到期分布、计提率、折旧率），5 个财年 + TTM，单位百万。模板和行定义见 `references/data-tables.md`。三条硬规矩：
- **表由脚本生成，不由模型手抄。** 跑 `python3 _system/scripts/render_tables.py {financials.json}`（skill 的 `scripts/` 目录里有同一份）得到 Markdown 表直接粘贴；模型只许加口径标记（`*` 不可比、`†` 并购年、`53w`）和表下注释，不许改数。A 股港股底稿没有脚本支持时才手填，并在表下注明"手填，未经脚本核对"。
- **一次性项目在这里就标出来。** 从底稿 `impairment / restructuring / checks 其他损益差额 / records.restated` 找候选，去附注核性质，列成一张表：年份、科目、金额、性质、是否剔除。后面第 1、2 步的比率同时给"含"和"剔"两版，第 4 步只做持续性归类，不再回头找一次性项目。
- **数据底座不进交接块。** 它是给人核对用的，交接块只放结论。

**0c 形态速判（≤3 行）。** 只看 0b 的比率速览，先定三件事：金融/REIT/非金融（决定 metrics.md 用哪套指标）、重/轻资产（固定资产/总资产、资本开支/收入）、营运资金为正/为负是否是行业常态（零售、订阅为负正常）。这三行是第 1 步体检选参照阈值的依据，不是结论，第 2 步问 1 会正式回答。

各项指标怎么算（ROIC、营运资金、增量利润率、再投资率、偿债与资产质量指标、TTM 怎么处理、金融公司用什么替代）统一按 `references/metrics.md`。**不同公司必须用同一套算法**，否则档案之间没法比。

## 第 1 步：财务安全体检——会不会出事、账实不实

**这一步和第 2 步只准用底稿和财务报表附注（10-K Item 8）里的数字。不读业务介绍（Item 1）、不读管理层讨论（Item 7）、不看 8-K 经营指标、不搜新闻、不看研报。**

先不管它怎么赚钱，先查两件事：**还不还得起**（偿债与流动性）、**账面资产是不是真的**（资产质量）。这两块不查，后面所有关于"生意有多好"的判断都可能建立在一个快出事或账面注水的公司上。

按 `references/health-check.md` 逐块做：

| 块 | 查什么 | 主要来源 |
| :-- | :-- | :-- |
| A1 债务规模与结构 | 净负债/EBITDA、租赁占比、到期分布、固定/浮动、契约、信贷额度 | 底稿 + 债务附注 |
| A2 偿付能力 | 利息覆盖、FCF/有息负债、5 年净借还 | 底稿 |
| A3 流动性 | 现金/1 年内到期债务、流动比率、受限现金 | 底稿 + 附注 |
| A4 表外与或有 | 租赁承诺、担保、诉讼、保理、未并表实体 | 附注 |
| B1 商誉与无形 | 占总资产、有形权益、减值 headroom | 底稿 + 商誉附注 |
| B2 应收 | 增速差、账龄、坏账计提、集中度、保理 | 底稿 + 附注 |
| B3 存货 | 增速差、构成、跌价计提 | 底稿 + 附注 |
| B4 软资产 | 资本化比例、递延税资产、折旧率变化 | 底稿 + 附注 |

每块结论三段：**看到什么 → 说明什么 → 红旗/黄旗/无**。红旗 = 12 个月内可能出事或账面明显失真；黄旗 = 趋势在恶化。阈值是提示不是判决，按第 0c 步的形态速判选参照（金融、重资产、负营运资金行业各有各的正常值），每个数给自身历史或行业惯例做参照，参照来自模型经验而非底稿时要注明"未核实"。

产出一张体检总结表（模板在 health-check.md 末尾）和**一句话结论：会不会出事、账实不实**。这句话进 F1；表进 F2。

体检的结论会喂给后面几步：租赁和固定利息进问 5 的固定成本；保理调整后的应收天数进问 3；资本化比例和折旧率变化进问 7；红旗必须在第 5 步对应至少一条判断。

## 第 2 步：只看数字，推断这是什么生意

**禁读范围同第 1 步。** 会员数、门店数、同店增速这类经营指标在 Item 1 和 8-K 里，属于第 3 步。就算你已经知道这家公司是谁，也当作不知道——只写数字能支撑的结论。

按 `references/seven-questions.md` 的七个问题逐一回答。每个问题的答案固定三段：

> **看到什么**（哪几个数、什么关系）→ **说明什么**（这是什么样的生意、处在什么位置）→ **如果这个推断对，还应该看到什么**（可以去验证的旁证）

| # | 问题 | 回答的是 |
| :-- | :-- | :-- |
| 1 | 这是什么形态的生意 | 重资产还是轻资产、毛利结构、周转快慢 → 大概属于哪类行业 |
| 2 | 钱从哪来、留下多少、被谁分走 | 收入→毛利→营业利润→净利润→自由现金流，每一层扣掉了多少、扣在哪 |
| 3 | 它在压谁、被谁压 | 现金转换周期、应付 vs 应收、预收款 → 在产业链里的议价地位 |
| 4 | 增长靠什么 | 增量利润率、再投资率 × 回报率、每块钱资本开支换来多少收入 → 规模效应是真是假、增长质量 |
| 5 | 成本里哪些是固定的、哪些跟着收入动 | 各项成本增速 vs 收入增速 → 经营杠杆、行业不好时利润会怎么摆 |
| 6 | 管理层把钱花在了哪 | 5 年资本配置去向和趋势 → 公司自己认为好项目在哪 |
| 7 | 哪里对不上 | 本该同向的数字反着走 → 异常清单 |

回答完写一段 **≤8 行的"数字画像"**：这大概率是一家做什么的公司、赚钱的引擎是什么、最强的一点和最弱的一点各是什么。这段话是第 3 步要拿去核对的靶子。

## 第 3 步：拿说法和数字对照

现在才读 10-K 的业务介绍和管理层讨论、最新 8-K 经营指标、月度销售公告（若有）、电话会、市场共识（联网）。8-K 和月度公告常比底稿新一个季度，是"数字有没有变向"的最早信号。目的不是补充信息，是**找对不上的地方**。

列一张对照表（进 F5）：

| 谁在说 | 说法 | 数字怎么说 | 一致 / 不一致 / 数据不足 |
| :-- | :-- | :-- | :-- |

只列公司或市场真在讲的说法（"有规模效应""有定价权""在转订阅""份额在涨"），不自己编一个来反驳。**一致的地方一句话带过，不一致的地方展开写**——那是这份报告最值钱的部分。第 2 步的数字画像被公司说法推翻的地方，要写清是数字有问题（口径、缺口）还是说法有问题。

## 第 4 步：分清哪些利润能持续

用第 0b 步已标出的一次性项目，把最近财年和 TTM 的营业利润拆成四块：**生意本身产生的**、**行业周期带来的**（景气、价格、汇率）、**一次性的**（资产处置、减值、诉讼、税务返还、疫情基数）、**会计处理带来的**（准则变更、折旧年限、资本化政策变化）。拆不开的写"无法分离，暂按生意本身处理，已标注"。

只有第一块可以往后推。据此给出**可外推的历史基线**（进 F3）：剔除一次性项目后的利润率和各项比率，附一行说明剔了什么。

---

## 第 5 步：给出判断，并说清什么情况下算判断错了

写 3–5 条判断（进 F6）。第 1 步有红旗的，至少一条判断要回答"这个红旗会不会变成事"。**至少一条判断要回答利润率天花板**：净利率/营业利润率还有没有往上走的空间，被什么锁住（税、补贴、费用率、行业定价），什么数字出现算"锁打开了"。这条判断会被 07 直接引用来判定机会类型（复利型看它还能不能扩，修复型看它是不是在回归）。每条固定四段：

> **判断**（一句业务结论，不是比率描述）→ **为什么**（数字为什么会这样）→ **什么情况说明判断错了**（哪个指标到什么数值）→ **谁去验证**（03 / 06 / 04 / 下季财报 / 需要管理层解释）

"毛利率 42%"不是判断。"毛利率靠的是对渠道的议价能力而不是产品本身，前三大客户占比再升 5 个点，毛利率就会往下走"才是判断。写不出"为什么"和"什么情况算错"的判断，不要写。

## 分析纪律

- 先核口径、摆数据，再算数；先查安全，再看生意；先看数字，再看说法；对不上的地方比对得上的地方重要。
- 正文引用的每个数都能在第 0 步数据底座里找到，或注明出自哪份附注。数据底座的数由脚本生成，模型不改数。
- 每个判断标明是"事实"、"判断"还是"假设"。每个关键指标至少给一个参照（自身历史或行业惯例）；给不出参照的指标，可能根本不该算。
- 变化比绝对值重要。毛利率从 45% 掉到 38% 的公司，比一直 40% 的更值得写。
- 不说"盈利能力较强"这种话。要说"净利率从 X 升到 Y，主要因为毛利率扩张，原因是……"。
- 拿不到的数写"未获取"，记进 F1 和 F7，不猜。F2 的旗、F5 / F6 / F7 宁可少写，不许凑数——没有红旗就写"无"，不许为了显得严谨硬凑一个。
