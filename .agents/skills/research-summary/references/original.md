# 研究总结生成 Skill

生成综合研究总结 HTML 文件，结构基于 `assets/template.html`。

## 输入收集

从用户提供的分析文档中提取以下信息（**不使用网络搜索**）：

- **公司名称 + 股票代码**：从文档标题或正文中读取
- **分析基准日 + 当时股价**：从文档中读取；如文档未注明，询问用户
- **投资评级**：从估值/结论文档中读取；如文档中有明确结论则直接使用

若某个维度的文档缺失，在对应 section 中如实注明"暂无数据"，不得凭空编造内容，也不得自行联网补充。

## 信息提取流程

依次读取用户提供的文档，按以下映射关系提取各维度内容：

1. **企业文化 / 公司治理** → 来自企业文化、使命愿景、公司治理、领导力相关文档
2. **商业模式** → 来自商业模式分析文档
3. **财务状况** → 来自细致财务分析文档（历史财务数据、KPI、优劣势）
4. **股性分析** → 来自股性分析文档（历史股价阶段、驱动因素、估值工具建议）
5. **财务预测** → 来自财务预测文档（三情景、预测表、监测指标）
6. **估值分析** → 来自估值分析文档（DCF、相对估值、目标价、操作区间表）
7. **战略决策**（有 `04_战略决策.md` 时增设）→ 核心战略判定、说的 vs 做的、证伪信号

## ⚠️ 写作规范（语言层，硬约束——用户明确要求，2026-08-04 新增）

**本 skill 的读者是投资决策者本人，不是卖方研究的同行。**判断标准只有一条：一个不做医药/半导体行业的人，第一遍读能不能读懂在说什么。历史教训：UNH 首版总结信息完整、数字准确，但被用户直接退回，原因是"不容易读懂"——长句套长句、英文缩写裸用、结论埋在句子末尾。

写每一句话之前先过一遍下面八条：

1. **一句话只讲一件事。句长 ≤ 40 字。**
   用破折号、分号把三四个事实串起来的长句，一律拆成 2–4 个短句。
   ❌「Hemsley 二次任期靠主动放弃约 160 万会员 + 四条线 6–11% 重定价，把赔付率从 89.1% 拉回 86.7%，承保修复是真的，但其中约 50% 是不可重复的一次性红利。」
   ✅「赔付率从 89.1% 降到 86.7%。靠两件事：赶走约 160 万不赚钱的参保人，四条业务线涨价 6–11%。修复是真实的。但其中约一半明年再也没有——赶人、涨价都只能做一次。」

2. **结论先行。**每段第一句就是结论，后面才给数字佐证。不要把结论埋在长句末尾。

3. **专业术语首次出现必须给白话解释**，写在括号里，≤15 字。**全文不得有裸用的英文缩写**（首次出现必须带中文名 + 解释）。示例口径：
   - MCR / 医疗成本率 → 赔付率（每收 100 元保费赔出去多少）
   - PYD → 往年赔款预提多了，今年冲回变成利润
   - PBM → 药品福利管理，替雇主和保险公司管报销与回扣
   - 主锚 → 给这只股票定价时市场实际看的那个指标
   - 前瞻 PE → 股价 ÷ 明年的每股盈利
   - 一票否决级 → 这条一旦发生，其他利好都不算数
   行业不同术语不同，但规则一样：**先给中文名，再给一句人话，然后才用它。**

4. **数字要有参照系。**任何数字后面要能看出"这算好还是坏"——给同比、给阈值、或给历史区间。裸奔的数字必须补比较基准。

5. **少用书面语虚词。**"即""故""属""系""业已""藉此" → "也就是说""所以""是""已经"。

6. **每个 section 开头加一句导语**，≤30 字，说明这一节回答什么问题。

7. **文末必须有「术语速查」小节**：两列表格，术语 → 一句话人话解释，收全文出现过的专业词。

8. **一句话画像不是一个长句。**拆成 4–6 个短句，每句一个要点，最后一句给评级与目标价。**第二句固定写机会类型**（取估值报告 §4.0 的一句话，例："这是复利型生意，股价走台阶，现在赚的是估值修复的钱"），第三句写持有方式。

**改写不得越界**：语言怎么改都行，但数字、日期、比例、目标价、评级、区间、结论方向、以及【假设】/【未检索到】的标注，一个字都不能动。

## HTML 生成规范

1. **读取** `assets/template.html` 作为结构基准
2. **逐一替换**所有 `【占位符】` 内容，不保留任何未填写的 `【】`
3. **评级颜色规则**：
   - section-rating badge：`badge-buy`（买入）/ `badge-hold`（持有）/ `badge-sell`（卖出）
   - 维度评级 span：`rating-A` / `rating-Aminus` / `rating-Bplus` / `rating-B` / `rating-C`
   - KPI 数字颜色：正面指标用 `pos`（绿）/ 负面用 `neg`（红）/ 中性用 `neutral`（橙）
4. **推荐框**：买入用 `.buy-box`，持有用 `.hold-box`，卖出用 `.sell-box`；HTML 中只保留对应一个，其余两个连同注释标记一起删除
5. **估值进度条 width**：`= 该方法目标价 ÷ 所有方法中最高目标价 × 100%`，确保比例视觉上正确
6. **三情景卡片**：三张情景卡都填一句话叙事与目标价；主导情景卡标题加 ★主导。**不输出概率加权目标价**——主导情景判定框（判定+置信+依据）与情景切换路标表必须完整填写，信号须含可核对的阈值
7a. **回报拆解小表**（估值 section 内、三情景卡片之下）：三行——盈利增长 / 估值倍数变动 / 股东回报，各给百分点与占比，数据取估值报告 §4.0 回报拆解表；表下一行写"改变类型的唯一开关"。模板缺该占位时在估值 section 末尾追加一个与操作区间表同样式的小表。
7. **估值方法条**：各方法各一根条，**主锚方法的标签加「主锚」标记**（主锚 = 估值报告依据股性分析选定的方法）；「主导情景目标价（主锚方法）」条的数值必须等于主锚方法在主导情景下的结果——**不输出方法加权价**，其余方法条是交叉校验参考
8. **不保留模板注释**（`<!-- ... -->`）——除 `<!-- ===== N. 章节名 ===== -->` 章节分隔注释外，其余模板说明注释全部删除
9. **存在 `04_战略决策.md` 时**增设「战略决策」section（核心战略判定 / 说的 vs 做的 / 证伪信号），样式与其余 section 一致。
   ⚠️ **位置固定在「股性分析」之后、「财务预测」之前**，即第五节——章节顺序必须与分析的依赖关系一致：
   `一、企业文化与公司治理 → 二、商业模式 → 三、财务状况 → 四、股性分析 → 五、战略决策 → 六、财务预测 → 七、估值分析 →（八、术语速查）`
   **战略决策是财务预测与估值的上游。（编号迁移后战略决策=04，编号顺序已与依赖顺序一致；此规则保留以防回归。）**（用户已因此退回两次）
