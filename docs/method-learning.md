# 潮石方法学习报告

这套方法的核心，是把公司判断连成一条可追踪的研究链：原始资料进入分析，分析形成预测，预测变成可核对的信号，估值根据这些信号判断公司正在走哪条路。后续财报和事件再回来检验原判断。它已经包含不少可运行脚本，也明确保留了人的研究和接受环节。它不是按一下按钮就能独立完成投资判断的软件。

以下“原方法”来自同僚仓库固定提交 `e5b147afa1b2c49bb9a6651094958538d5802a59`。评论是这次迁移的独立评价，不是原作者的结论，也没有引入其他投资框架。没有迁入同僚的公司案例、目标价或持仓。

## 这套系统怎样产生一份研究

新公司先登记身份和目录。原流程自动寻找定期报告、电话会纪要和财务底稿。找不到的项目应留记录，不能把“没有下载成功”说成“公司没有披露”。入库不会自动产生研究评级。

完整研究分七份。文化由使命愿景、领导力、治理三份合并；财务先看数字；股性看长期价格与历史定价方式。这三路先做。商业模式接着用财务事实检验客户、需求和赚钱方式。战略分析再核查公司究竟把资源投向何处。预测把这些判断转成三套未来路径。估值最后判断现实更接近哪条路径，并选合适的定价方法。

| 分析 | 原方法真正要回答的事 | 交给下一步什么 |
|---|---|---|
| 01 企业文化 | 口号与行为是否一致，管理层能否兑现，激励是否一致 | 执行能力、行为约束、治理风险 |
| 02 财务分析 | 是否安全、账是否可靠、数字显示什么生意 | 历史基线、利润质量、资本使用及疑点 |
| 03 商业模式 | 什么客户为何付费，价值交换能否持续 | 增长方式、空间、竞争约束 |
| 04 战略决策 | 公司实际上在改变什么，钱和行动是否支持说法 | 三情景条件、财务变量、时间路径、定价方法可能变化的条件 |
| 05 股性分析 | 价格过去受什么驱动，市场常用什么尺子 | 历史定价依据、倍数区间与价格表现类型 |
| 06 财务预测 | 哪些假设使未来分成三条不同路径 | 可复算预测、差异最大的驱动因素、可观察指标与阈值 |
| 07 估值分析 | 现实更像哪条路径，这个状态值多少钱 | 主导情景、目标价、条件明确的切换信号及登记信息 |

这里最有用的设计，是交接不只传一个“看好”或“不看好”。例如战略报告提出某条产线将在某时点释放产能，预测必须说明如何转成收入、利润和资本开支。估值用到同一项信号时，也不能重新编一套阈值。这样才能追出一处错误影响了哪些下游判断。

草稿先进入待审目录。用户可以讨论、修订、接受或退回。接受后才成为正式档案；被替换的版本留下。总结页只把这些档案讲清楚，不应新增证据或偷偷改变数字。换 Codex 会话后从文件继续，不靠模型记忆维持状态。

## 值得保留的地方

**先看数字，再看故事。** 财务技能刻意延后管理层叙事，先检查偿债、流动性和资产质量，再从数字倒推生意。这能减少先相信故事、再挑数字证明的倾向。但行业背景仍会影响会计解释，因此“后看叙事”不等于“不需要领域知识”。发现异常必须回到原始披露核口径。

**把判断写成能被推翻的条件。** 预测的分歧驱动表要求可观察指标、互不重叠的阈值和核对时点。事件更新不能临时凭印象重定价。它应先问：新事实触碰了哪一条已登记条件？这能让研究更连续，也便于承认原判断错了。

**把慢变化和快变化分开。** 战略是首次建档必做项，但不是每季机械重做。季报通常更新预测与估值；换管理层、重大并购或战略转向才可能需要重审战略。是否重做由事件对原假设的影响决定。

**保存决定当时的依据。** 待审、正式、历史和事件记录分开，避免把修订后的判断冒称过去已经知道。对投资研究而言，保存版本至少与生成一份漂亮报告同样重要。

## 需要警惕的前提

**三情景与阈值并不是客观真理。** 原方法禁止把三种互斥状态平均成一个目标价，改为选主导情景。它的好处是目标价对应一个可解释的公司状态。代价是阈值附近可能突然换情景，而现实变化可能是连续的。三个情景本身也可能漏掉重要路径。报告应保留阈值附近的敏感性和反证，不能把计分结果称为已被证明的未来。

**计分会受指标选择影响。** 分歧表只有少量主要驱动因素。如果几个指标其实都受同一因素驱动，多行命中可能是在重复计算同一证据。数据缺失还可能改变分母。需要检查指标独立性、缺失范围与第一关键指标，不能把行数当作胜率。原偏差分诊中的“过半”“前三行”是流程阈值，不是经过此项目验证的统计定律。

**因果判断比表格困难。** 文化、领导力、治理和战略都要求从行为推原因。成功可能来自行业顺风，失败也可能来自当时合理但不走运的选择。原战略技能已经要求反事实、失败案例和战略时期划分，这些要求应保留。仍不能因为找到三个历史事件，就认定未来有稳定规律。证据置信度和企业质量评级也不是同一个数。

**精细预测不保证精确。** 五至十年的预测表容易给人确定感。收入、利润率、资本投入和最终长期价值对少数假设很敏感。底稿能勾稽，只说明算术与口径可检查，不说明商业假设成立。应先检验影响最大的假设，保留不确定区间，再谈精细小数。

**市场过去的尺子可能失效。** 股性提供历史依据，战略尝试判断公司是否会改变类型。但“过去用收入倍数，所以未来也会用”并不可靠；“公司转型，所以一定重估”也不可靠。原方法要求用实际条件确认定价方法变化，这个限制比目标价本身更重要。

**原始数据也需要核对。** 自动财务抓取会遇到公司特有标签、残差科目、重述、财年变化和币种变化。程序标出的未命中不是零，报告日期也不总是数据覆盖日期。A 股、港股、金融企业及外币申报不能因为文件下载成功就被视为同等可用。每个市场要看实际可获得的底稿和口径。

**定时执行不等于无人研究。** 行情、信号、页面和模拟盘可以由确定性脚本更新。新闻核验、事件归因、研究修订仍需要正在执行的 Codex 或另行接通的 AI 调度。一个定时配置文件或一份空简报不能证明全流程自动运行。空研究库也没有可展示的策略表现。

## 原材料的缺口与冲突

最实质的缺口在 04 战略技能。原文要求先读三份参考文件，但固定提交没有提交它们。当前保留现存八步正文及明确给出的交接模板，可以产出注明限制的草稿；不能声称恢复了完整研究协议与原报告模板。这不是用户需要逐项审批的技术问题，处理方式是记录缺口、降低“完整复刻”的表述，并在以后取得原件时补齐。

原仓库是持续演化的系统，一些旧段落没有同步：旧建档说明让人改已删除的公司常量；新入库已经从统一注册表读取。旧扫描还写“加权目标价”和旧模块号，但新估值明确禁加权。旧文档把完整状态定义为六份，是为补建战略的存量公司过渡；本项目从空白开始，应当七份齐全。

事件更新原文同时要求按依赖先后生成，又要求所有上游读正式版。这会让同批的估值读到旧预测。本地适配采用“同批已完成的新上游优先，未刷新的上游读正式版”，并保存版本指针。它解决执行矛盾，没有改变研究方法。

独立 VC 风格技能允许主观概率加权回报，核心估值禁止加权目标价。两者可以各自研究，但不能把结果混成同一条正式定价链。本地保留该补充技能，必须明确调用，输出另存；核心七模块继续使用原 valuation-analysis。

此外，原文化独立技能与三路文化合并并存；本地保留原全量编排，不擅自替换。研究总结目录中的示例脚本和 API 文档只是空脚手架，没有真实功能，不能算已迁移能力。具体差异见 [方法对应与验证记录](method-map.md)。

## 怎样判断以后研究是否有用

先看它是否改变了一个可观察的判断，而不是看页数。公司靠什么赚钱？最关键的一个假设是什么？最新证据支持还是反驳它？若判断错了，哪份材料最早会显示出来？目标价依赖哪个状态，什么时候必须重算？这些问题应能在正式档案里找到简短答案和可追溯依据。

程序能帮助保存答案、提醒缺口、核算数值和避免误覆盖。它不能替研究者保证解释正确。每次接受研究时，值得讨论的是最重要的假设与证据，而不是逐项审核脚本和文件格式。
