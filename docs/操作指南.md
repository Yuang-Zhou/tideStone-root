# 使用指南

[项目首页](../README.md) · [文档索引](README.md)

首次安装见项目首页。以下命令均在项目根目录执行；研究、修订和接受操作也可直接在 Codex 中提出。

## 研究流程

公司入库 → 材料准备 → 七模块分析 → 待审 → 修订或接受 → 正式档案与总结。

| 阶段 | 工作与结果 |
| --- | --- |
| 入库 | 核实公司与证券身份，创建目录并登记日常跟踪；尚不生成报告、评级或目标价。 |
| 材料 | 收集公开报告，保存来源、期间和内容指纹。财务数据核对币种、单位、财年及会计口径；缺失和冲突单独记录。 |
| 分析 | 按依赖顺序完成文化、财务、商业模式、战略、股性、预测和估值七个模块，保存为待审稿。 |
| 修订 | 先保存原稿，再修改受影响模块并重新校验。修改目标价时同步检查上游假设。 |
| 接受 | 用户明确接受指定批次后，保存正式档案和历史，同步估值，并生成有来源的研究总结。 |
| 更新 | 新财报或事件先做偏差与影响分析，再更新必要模块，结果仍进入待审流程。 |

常用请求：

> 研究某家公司，准备公开材料，完成七模块分析并提交待审稿。
>
> 修订这一批预测和估值：请核对收入增长假设，说明修改依据。
>
> 接受已展示的这一批草稿，保存正式档案并生成研究总结。
>
> 继续潮石研究，先读取当前待审稿、材料缺口和未处理事件。

退回时说明批次和理由，原稿与上一版正式档案会保留。程序校验、Git 提交和 PR 合并都不构成研究接受。估值登记缺项时保留“待补”；主目标价与三年目标价分别标明期限、币种和来源。

## 阅读页面

运行 `python3 scripts/ops.py start`，打开 [http://127.0.0.1:8791](http://127.0.0.1:8791)。服务仅监听本机，关闭页面不影响资料保存。

| 页面 | 内容 |
| --- | --- |
| 公司总览 | 材料、模块状态、待审批次与事件 |
| 研究报告 | 草稿、正式档案、总结及历史版本 |
| 目标价对比 | 已接受估值、三年目标、行情日期及缺项 |
| 每日简报 | 实际完成并保存的研究扫描 |
| 模拟盘 | 独立虚拟记账；未初始化时为空 |

正式档案合订本按七模块汇编，研究总结则需单独生成并登记。资料更新后运行 `python3 scripts/ops.py build` 刷新页面。

## 配置与取数

依赖安装在 `.venv/`，版本记录见 [requirements-market.lock.txt](../config/requirements-market.lock.txt)。运行工具优先使用该环境。

美股 SEC 取数需要应用名称和真实联系邮箱。首次配置时，将 [local.env.example](../config/local.env.example) 复制为 `config/local.env`，取消示例行注释并填写自己的标识。此文件由 Git 忽略。

按已登记证券代码准备材料：

```sh
.venv/bin/python scripts/data_update.py TICKER
```

将 `TICKER` 替换为实际代码。各市场的数据源与脚本适用范围不同，执行结果保存在公司 `_fetch_runs/`。访问失败、材料缺失和不适用项会分别记录；也可提供本地原始报告，由材料入口登记来源。

## 日常维护

```sh
python3 scripts/ops.py daily
python3 scripts/ops.py status
```

日常维护依次处理行情、技术信号、已启用模拟盘、数据校验、档案状态、历史归档和页面，并保存日志。`daily --offline` 使用已有行情，仍会执行其他本地维护步骤，可能更新状态与虚拟账本。

**AI 新闻扫描由用户在 Codex 发起。**本机维护任务没有常驻 AI 执行器，数据更新成功与研究扫描完成分别记录。

暂停或恢复公司跟踪：

```sh
python3 scripts/tidestone.py track TICKER --status paused --reason "暂停跟踪"
python3 scripts/tidestone.py track TICKER --status active --reason "恢复跟踪"
```

暂停保留材料与研究，退出新闻扫描和模拟盘候选；已有虚拟持仓将在下次纸面运行按出池规则处理。跟踪状态与研究完成度独立。

模拟盘需单独初始化，资金、汇率、成本、滑点与整手假设均须明确。行情过旧时限制新交易；配置中的固定汇率需核对。模拟盘不连接真实交易账户。

### macOS 定时任务

首次在本机配置时执行以下命令。已有任务需要更换项目路径或 Python 环境时，先运行 `python3 scripts/ops.py schedule remove` 卸载，完成变更后再重新配置：

```sh
python3 scripts/ops.py schedule prepare
python3 scripts/ops.py schedule install
python3 scripts/ops.py schedule status
```

默认计划为本机时间 08:30，并在加载时执行一次。希望按北京时间运行时，应将系统时区设为 Asia/Shanghai。任务需要登录会话，睡眠或断网可能影响执行。

克隆仓库不会自动安装任务，仓库中的 `config/scheduler_status.json` 是原机器记录。通过 `schedule status` 和 `runs/scheduled.*.log` 核验本机状态。停止定时任务用 `python3 scripts/ops.py schedule remove`。

## 备份与恢复

### GitHub 版本

私有仓库保存已提交并推送的代码、方法、材料、研究状态与实际运行日志。本机凭证、环境、缓存、生成网页、重复压缩包和测试恢复副本由 [.gitignore](../.gitignore) 排除；[.gitattributes](../.gitattributes) 保持文件原始字节。

日常更新按[贡献指南](../CONTRIBUTING.md)提交并推送。换电脑时重新克隆，按项目首页安装依赖、读取状态并启动页面；本机配置与定时任务另行设置。

### 本地压缩备份

```sh
python3 scripts/ops.py backup
```

压缩包及校验清单保存在 `backups/`，包含研究资料、方法、代码、文档、实际运行日志和配置；本机 `config/local.env` 若存在，也会进入压缩包。虚拟环境、生成网页与进程状态不在其中。

恢复时使用项目内的空目录，并保留压缩包旁的 manifest 文件：

```sh
python3 scripts/ops.py restore backups/文件.tar.gz --to runs/restore-check
```

恢复会检查归档及逐文件内容指纹，不覆盖现有非空目录。先核对恢复结果，再决定如何接续工作。本地压缩备份与 GitHub 版本备份独立，`backup` 命令不会上传到 GitHub。

## 命令参考

| 操作 | 命令 |
| --- | --- |
| 读取研究状态 | `python3 scripts/tidestone.py status --json` |
| 页面管理 | `python3 scripts/ops.py start`（`start` 可替换为 `build` 或 `stop`） |
| 读取运行状态 | `python3 scripts/ops.py status` |
| 登记总结 | `.venv/bin/python scripts/register_summary.py TICKER --markdown 文件.md --html 文件.html` |
| 研究命令帮助 | `python3 scripts/tidestone.py --help` |
| 运维命令帮助 | `python3 scripts/ops.py --help` |

总结须基于七份已接受档案，保存为公司目录下同名的 `研究总结_<时间>.md` 和 `.html`，登记后才会显示在页面中。
