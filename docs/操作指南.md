# 从“我想研究某家公司”开始

在 Codex 打开 `/Users/yuangzhou/Desktop/tideStone-root`。你主要和 Codex 对话，网页负责展示实际保存的成果。你不需要先填写长表格或学习命令。

## 1. 建立第一个标的

可以说：

> 我想研究某家公司，请按潮石流程开始。先核实公司身份和上市代码，再准备材料，做到可供我讨论的待审稿。

Codex 会确认是哪家公司、在哪个市场上市，把它加入你的空白研究库，建立材料目录并查找公开报告。存在同名或多种证券且不能自行判断时，才需要你选择。

入库默认进入日常跟踪名单，但不会产生评级、目标价或研究结论。网页此时显示“待研究”，七份模块显示缺失。资料下载失败会留下来源、错误和受影响模块；不会把下载清单当成财报本身。

美股 SEC 自动取数需要你提供自己的联系邮箱作为公开取数请求标识。可对 Codex 说“用这个邮箱配置 SEC 取数标识：……”。它不需要 SEC 登录、券商权限或 OpenAI API 密钥。未配置时，其他可执行的公开资料准备仍会继续；可以提供原始报告，由 Codex 登记来源和日期。网站、网络或付费材料的访问限制不能靠本系统消除。

## 2. 准备和核对材料

可以说：

> 为这家公司补齐年报、最近季报、电话会和治理资料；告诉我哪些资料仍缺、会影响什么判断。

也可以把本地文件放进项目，再告诉 Codex 路径。系统会保存一份带来源、期间和内容指纹的副本。后来替换一份资料，会留下另一条记录，不会悄悄改掉原研究依据。

财务底稿先核币种、单位、财年、会计口径及勾稽；能获取某个数字不代表数字已经适合用于分析。对缺失、冲突或无法解释的项目，Codex 应写明原因，不把它当零。

## 3. 读七个模块的待审稿

可以说：

> 按潮石原方法完成完整分析，先给我核心判断、最重要的不确定性和待审稿。

七份档案分别是：企业文化、财务分析、商业模式、战略决策、股性分析、财务预测、估值分析。它们有先后关系：财务数据先用来检验商业模式，再把文化、业务和战略传给预测，最后结合股性确定估值方法。

复杂分析可能持续较长时间。网页上的“待审批次”会指向实际草稿；还没产生内容的模块不会显示完成。程序校验检查保存和交接条件，不能证明投资判断正确。

打开 [本地网页](http://127.0.0.1:8791)：

- **公司总览**看材料数、模块状态、待审批次和新事件。
- **研究报告**读草稿、正式档案、总结和历史。正式档案合订本按七个模块汇编，不能代替另行生成的研究总结。
- **目标价对比**看原估值、三年目标、行情日期及缺项。不同期限与币种必须分别识别；缺数字就留空。
- **每日简报**只列真正完成并保存的扫描报告。没有做新闻分析时不会补一份空泛“日报”。
- **模拟盘**独立虚拟记账，不连接真实账户。尚未初始化时保持空白。

## 4. 追问和修订

可以说：

> 你为什么认为这家公司有定价权？请指出支持和反对的材料。
>
> 基准收入增长看起来太乐观。请对照订单、续约和竞争证据重新判断，并更新受影响的预测和估值。

追问本身不会修改正式档案。要求修订时，Codex 会先保存原草稿，再修改本批次，并给出差异和理由。不能只改目标价而不检查上游假设。改完后再次校验，仍然等待你接受。

## 5. 接受或退回

满意时说：

> 接受刚才展示的这一批草稿，保存为正式档案，并生成研究总结。

Codex 会核对明确批次，保存上版历史，晋升新稿，同步本次估值及三年目标，生成日期版 HTML 和 Markdown 总结，再更新网页。若估值登记不完整，页面显示待补，不能自行填数字。

不满意时说：

> 退回这一批，理由是对竞争对手的核验不足。先补材料再重新提交。

被退回稿仍然保留；上一版正式档案不受影响。你也可以只要求修订而不退回整批。完整研究授权不等于提前接受结论。

## 6. 有新财报或新事件时

可以说：

> 这家公司出了新财报。先对照原预测，列偏差及可能原因，再告诉我哪些判断需要更新。
>
> 公司宣布了一项新并购，请保存事件来源，评估影响并更新必要模块，完成后给我待审稿。

“预测偏差分诊”先比对当时已经登记的驱动指标，不临时换一组更好看的指标，也不会自己改正式结论。原方法支持范围有限；数据不足时应写“无法核”。

事件更新先判断影响范围，再只更新必要模块。正式档案、旧预测、新材料、修改理由与接受记录都会保留。上游单独改变而下游尚未重算时，需要明确提示仍待更新。

## 7. 换聊天或重新启动后继续

可以说：

> 继续潮石研究。先读磁盘状态，告诉我上次有哪些待审稿、缺失资料和未处理事件，再继续未完成的部分。

状态存在项目文件中，不依赖上一段聊天记忆。重新打开 Codex 时项目 Skills 应自动出现；如果当前聊天尚未刷新，直接让 Codex 读取 `AGENTS.md` 和项目内 `tidestone-research` Skill 即可。

## 8. 日常维护和模拟盘

可以说：

> 执行一次潮石日常更新，说明实际成功与失败的步骤。
>
> 运行每日研究扫描，重点看哪些新事实会改变现有判断，保存简报。
>
> 初始化潮石模拟盘，使用十万美元虚拟资金；先说明策略、汇率和成交假设。

本机维护任务按原宿主流程适配，在北京时间 08:30 更新行情、技术信号、已启用模拟盘、数据校验、档案状态和页面。macOS 必须登录且可运行任务；睡眠、断网、系统权限可能延迟或阻止执行。日志记录实际结果。

**Codex 的 AI 新闻扫描目前由你在聊天中发起。**已安装的本机任务没有独立模型服务，也没有偷偷调用 API。自动数据维护成功不代表当天新闻已分析、研究已更新或草稿已接受。

可以说“暂停跟踪这家公司，保留研究资料”或“恢复跟踪”。暂停会退出新闻扫描和模拟盘候选；若已有虚拟持仓，下次纸面运行按出池处理，应先核对影响。跟踪状态与七模块是否完成互相独立。

模拟盘保留原“低估＋增长”规则及退出迟滞，使用虚拟收盘成交、成本与整手假设。行情过旧时不能宣称新鲜成交。汇率在原配置中是常数，需要核对；原规则不是已经被证明有效的策略。正式库没有初始化账户或持仓。

## 9. 启动、停止、备份、恢复

可直接对 Codex 说“启动潮石”“停止潮石网页”“更新网页”“备份潮石”“把某份备份恢复到独立目录供核对”。本目录也有三个可双击入口：启动、停止、备份。

停止网页不会删除研究。备份包含研究资料、方法、代码、配置与文档；页面可重新生成。恢复默认只允许写入项目内的空目录，先核验每个文件，避免覆盖当前工作。备份与原数据仍在同一台电脑；如需防整机丢失，应另行明确要求复制到你指定的备份盘。

当前网页地址为 [http://127.0.0.1:8791](http://127.0.0.1:8791)。它只监听本机，未向互联网发布。

## 给 Codex 的操作索引

以下是辅助入口，不要求用户手动输入：

| 工作 | 项目根目录下的命令 |
|---|---|
| 读状态 | `python3 scripts/tidestone.py status --json` |
| 自动准备材料 | `.venv/bin/python scripts/data_update.py TICKER` |
| 暂停 / 恢复跟踪 | `python3 scripts/tidestone.py track TICKER --status paused --reason 理由`；恢复时将 paused 改为 active |
| 登记实际研究总结 | `.venv/bin/python scripts/register_summary.py TICKER --markdown 文件.md --html 文件.html` |
| 生成网页/正式档案合订本 | `python3 scripts/ops.py build` |
| 启动 / 停止网页 | `python3 scripts/ops.py start` / `python3 scripts/ops.py stop` |
| 手动日常维护 | `python3 scripts/ops.py daily` |
| 仅检查已有文件 | `python3 scripts/ops.py daily --offline` |
| 备份 | `python3 scripts/ops.py backup` |
| 恢复到独立目录 | `python3 scripts/ops.py restore backups/文件.tar.gz --to runs/restore-check` |
| 核对定时运行 | `python3 scripts/ops.py schedule status` |
| 停用 / 恢复定时 | `python3 scripts/ops.py schedule remove` / `python3 scripts/ops.py schedule install` |

SEC 标识保存在 `config/local.env`，样式见 `config/local.env.example`。不把同僚的邮箱或账户复制成你的身份。市场依赖保存在项目 `.venv`；固定安装记录在 `config/requirements-market.lock.txt`。操作脚本自动选择该环境。
