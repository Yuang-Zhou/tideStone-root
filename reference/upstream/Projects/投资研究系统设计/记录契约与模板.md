# 记录契约与模板

版本：proposal-v1｜日期：2026-10-09｜状态：设计模板，非已经运行的数据接口。

所有尖括号占位符均须填写或明确留空。未知值用`null`并说明原因，不能填0冒充未知。公司键可沿用现有ticker，并加稳定`company_id`以处理更名、多地上市、ADR比例变化等问题。

## 一、记录之间的关系

```text
来源 S → 观察 F → 判断 H → 预测 P → 结算 O
                    ↓         ↓
                  模型 M → 决策 D → 成交/结果 X → 复盘 R
                    ↑                             ↓
                    └──────── 方法规则 U ──────────┘
```

市场价格也是观察，管理层观点是来源主张。成交记录的权威来源应为账户/经纪商执行数据；下列决策卡只保存执行引用。

## 二、最小必填集与扩展字段

| 对象 | 初期必填 | 后续扩展 |
|---|---|---|
| 来源 | ID、来源类别、原文件、发布日期/未知、抓取日期、哈希 | 原始来源簇、许可/访问限制、OCR信息 |
| 观察 | ID、内容/数值、期间、口径、来源定位、核验状态 | 公式、重述链、可比性映射 |
| 判断 | ID、版本、主张、证据/反证、期限、失效条件 | 替代解释、参考类、影响路径 |
| 预测 | ID、版本、问题、冻结时间、结果规则、预测值、截止 | 基准预测、固定提前期、概率校准分组 |
| 决策 | ID、策略、期限、时间、选择与理由、风险条件 | 机会成本、替代动作、执行基准 |
| 发布 | ID、生效时间、输入版本、输出哈希 | 环境/公式版本、并发控制 |
| 复盘 | 原ID、结果、原规则结算、偏差类型、后续动作 | 跨公司模式、经验规则验证 |

初期可把这些记录写在少量Markdown表格中，而不为每个字段开发数据库。关键是信息不能缺失，权威值只在一处维护。

## 三、来源与观察模板

```yaml
schema_version: proposal-v1
source_id: TCOM-S-0001
source_type: company_filing  # transcript / third_party / price_feed / execution
origin_source_id: null      # 同源转述指向相同原始来源
title: <原始标题>
url: <来源URL或null>
original_path: <原文件路径>
sha256: <原文件哈希>
published_at: <ISO8601含时区或null>
recorded_at: <本次入库时间>
available_to_system_at: <实际可使用时间或null>
verification: pending      # checked / disputed / superseded
```

```yaml
fact_id: TCOM-F-0001
record_version: 1
kind: disclosed_observation # derived_metric / attributed_claim / schedule
statement: <观察内容，来源主张须明确主体>
metric: <指标名称或null>
value: null
unit: <RMB_million / percent / USD_per_ADS等>
effective_period: <起止日期或会计季度>
accounting_basis: <GAAP / company_non_GAAP / analyst_adjusted>
scope: <集团/分部/地区>
denominator_definition: <百分比的分母，或null>
source_id: TCOM-S-0001
locator: <页码/表名/章节/原文段落>
calculation: null
input_fact_ids: []
verification: pending
supersedes: null
restatement_reason: null
```

规则：`analyst_adjusted`若只是明确公式、客观输入的派生值可以存此；若包含选择性的经济判断，必须链接判断ID和调整方法版本，不能假装成公司原始披露。来源主张中的因果解释也不自动获得事实地位。

## 四、判断卡模板

```markdown
---
judgment_id: TCOM-H-0001
version: 1
issued_at: <时间>
data_cutoff_at: <时间>
status: draft
horizon: fundamental
provenance_mode: prospective # retrospective_import / illustrative
evidence_ids: []
input_judgment_versions: []
---

# 一句话可讨论的主张

业务机制：A通过什么机制影响B，再影响现金流/风险。
适用范围：业务线、时间、会计口径。
支持证据：列ID和定位。
反对证据：列ID和定位；无证据时写尚未找到，不能写不存在。
替代解释：至少一种能够产生相似观察的机制。
参考类：如何选、基准率、与本公司的差异。
信心：高/中/低及证据质量说明；不是事件概率。
失效条件：哪些观察足以使本判断被削弱或停用。
相关预测：P-ID。
模型路径：影响06哪些假设、07哪些输入。
下次复核：时间或事件。
```

状态建议：草稿→有效→待复核→被替代/停用。`confirmed`不是所有机制判断的必备终点；持续有效的长期机制仍可在未来改变。

## 五、预测契约

```yaml
forecast_question_id: TCOM-P-0001
forecast_version: 1
judgment_id: TCOM-H-0001
provenance_mode: prospective
issued_at: <结果未知时的时间>
data_cutoff_at: <允许使用的信息截止>
question: <在指定期间，按指定口径，指标是否满足明确条件？>
target_period: <期间>
resolution_window_end: <最迟结算时间>
forecast_type: binary  # point_mean / point_median / interval / distribution
probability: null      # binary才填写0到1
point_value: null
interval_level: null   # 只有具有概率含义的区间才填写
lower: null
upper: null
unit: <单位>
outcome_rule: <阈值，等号边界，单位，舍入方式>
source_priority: [<一手来源>, <后备来源>]
missing_rule: <未披露或不可比时怎样处理>
restatement_rule: <首次披露评分/另列重述后评分>
baseline_forecast: <同信息集简单基准及数值>
score_at_horizon: <固定提前期或预定时间权重规则>
correlation_cluster: <公司-事件-期间>
scoring_eligible: true
status: open
```

结算是一条新记录，不修改原预测：

```yaml
resolution_id: TCOM-O-0001
forecast_question_id: TCOM-P-0001
forecast_version: 1
resolved_at: <时间>
status: resolved # unresolvable / awaiting_publication
outcome: null
outcome_fact_ids: []
original_rule_applied: true
score_method: <binary_brier_0_1 / mae / interval_score等>
score: null
comparison_baseline_score: null
reason: <判定依据；不可判定必须解释>
```

规则：更新概率保留新旧版本；变更问题、期限或阈值建立新问题ID。事后补录问题设`provenance_mode: retrospective_import`和`scoring_eligible: false`，不进入前瞻成绩。未披露是缺失，不是0；取消问题也要保留，不能从分母中悄悄消失。

## 六、长期决策与短期交易卡

共用字段：

```yaml
decision_id: TCOM-D-0001
decision_at: <时间含时区>
strategy_id: <策略ID及版本>
capital_bucket: long_term # short_term
release_id: <所用研究发布ID>
action: observe # buy / sell / hold / skip / transfer
horizon: <明确期限>
data_cutoff_at: <时间>
price_observation_id: <价格记录>
alternatives: [<不做>, <其他可行行动>]
rationale: <为什么选择该行动>
risk_limits: <引用组合约束版本>
review_at_or_on: <日期或事件>
execution_ids: []
```

长期卡补充：价值区间及含义、市场隐含假设、预计持有期、关键证伪、买卖条件、分红/回购/稀释假设、组合相关性。不以固定三情景价自动生成“真实概率”。

短期卡补充：

```yaml
setup_id: <交易设想ID>
setup_status: planned # triggered / cancelled / expired / closed
signal_at: <信号实际生成时间>
valid_until: <最后有效时间>
entry_trigger: <可复现条件>
cancel_if: <取消条件>
order_type: <计划订单类型>
first_executable_at: <最早可成交时点规则>
stop_rule: <价格/条件/跳空处理>
profit_exit_rule: <规则>
time_exit_rule: <规则>
intrabar_ambiguity_rule: <同bar双触发如何处理>
planned_risk_amount: null
currency: <账户记账币种>
cost_model_version: <费用/滑点/融资假设>
signal_only_benchmark: <信号评价基准>
execution_benchmark: <成交评价价格与时点>
overlap_cluster: <同期相关信号簇>
```

实际交易回报从成交事实计算；未触发不算亏损交易，未执行也不能假装成交。信号评价、模拟计划、实盘成交三类样本分别保留。股票本币回报与账户基准币回报分别可核对。

## 七、发布清单

```json
{
  "schema_version": "proposal-v1",
  "company_id": "TCOM",
  "release_id": "TCOM-REL-<timestamp>",
  "published_at": "<timestamp>",
  "supersedes_release_id": null,
  "data_cutoff_at": "<timestamp>",
  "status": "draft",
  "fact_snapshot_id": "<id>",
  "judgment_versions": ["TCOM-H-0001@1"],
  "model_version": "<model-id>",
  "valuation_method_version": "<method-id>",
  "research_probabilities": null,
  "dominant_scenario": null,
  "allocation_policy_version": null,
  "files": [{"path": "<relative-path>", "sha256": "<hash>"}],
  "unresolved_issues": [],
  "approved_by": null
}
```

`research_probabilities`、`dominant_scenario`、`allocation_policy_version`不能互相覆盖。情景互斥且穷尽时概率和应为1；情景只是条件估值就明确无概率含义。主导标签可保留现有方法，但应可追溯到规则版本。

发布前验收：所有引用存在；输入版本明确；数字与币种一致；估值现金流来自指定06；关键依赖没有未解释的过期；未决问题被展示。发布后切换当前指针并同步生成登记表，避免读到混合版本。

## 八、更新与复盘模板

```markdown
# 某次事件后的判断更新

更新ID / 事件ID / 原发布 / 新发布 / 记录时间：

## 按原规则结算
哪些预测到期？结果与来源是什么？不可比项有哪些？

## 判断变化
| 判断ID | 旧判断 | 新证据 | 新判断 | 类型 | 影响下游 |
|---|---|---|---|---|---|

## 估值桥
现金流 / 折现 / 时间 / 净现金 / 股数 / 汇率 / 方法改变。
说明固定归因顺序、交互项和舍入差异。

## 决策复盘
事前证据是否充分？规则是否执行？实际结果如何？未选择方案如何？

## 偏差归因
数据错误 / 机制错误 / 参数错误 / 时间错误 / 情景遗漏 /
估值口径 / 执行成本 / 风险预算 / 暂无法判断。
允许多原因，不强迫分成互斥类别或给虚假百分比。

## 下一步
保留哪条规则；试验哪条规则；需要什么新证据；何时复核。
```

## 九、经验规则模板

```yaml
lesson_id: SYSTEM-U-0001
version: 1
status: candidate # trial / retained / retired
lesson: <具体可执行规则>
scope: <行业/公司类型/期限/市场条件>
supporting_review_ids: []
counterexamples: []
mechanism: <为什么可能有效>
next_prospective_test: <什么新样本可以验证>
effective_from: <仅对之后的新决策生效>
retire_if: <何种证据出现就停用>
```

禁止把“一次亏钱后的感想”直接变成跨公司永久规则。规则本身也要接受反馈。
