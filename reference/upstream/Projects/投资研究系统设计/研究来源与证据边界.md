# 研究来源与证据边界

研究日：2026-10-09。外部资料用于系统方法研究，本地资料用于诊断现有结构。未对TCOM公司事实进行新的外部核验。

## 外部方法来源

| 来源 | 类型与使用范围 | 不支持的推论 |
|---|---|---|
| [Mellers等，Psychological Strategies for Winning a Geopolitical Forecasting Tournament，2014](https://escholarship.org/uc/item/4rg4n9vr) | 原始研究；训练、协作、跟踪与概率预测质量 | 不能证明该目录方案或任何股票策略能产生超额收益 |
| [Gneiting与Raftery，Strictly Proper Scoring Rules，2007](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf) | 原始方法论文；概率与分布评分 | 分数好不自动意味着交易盈利；不能忽略问题难度与样本相关性 |
| [Reducing bias…with preregistration，Nature Human Behaviour，2023](https://www.nature.com/articles/s41562-022-01497-2) | 方法研究；事前定义、透明度与偏差控制 | 不要求预测形成后永不更新；更新要保留历史 |
| [Damodaran，An Introduction to Valuation](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/background/valintro.htm) | 作者教学材料；估值偏差、不确定性、模型与价值区间 | 不能用单次价格命中直接证明内在价值正确 |
| [CFA Institute，Risk Profiling Through a Behavioral Finance Lens，2018](https://www.cfainstitute.org/sites/default/files/-/media/documents/book/rf-publication/2018/risk_compilation_2018.pdf) | 专业机构资料；结果偏差与过程评价 | 不可用“过程正确”永久回避持续亏损证据 |
| [Bailey与López de Prado，The Deflated Sharpe Ratio，2014](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf) | 原始研究；多次试验、选择偏差与绩效夸大 | 少量个人交易不能据此自动认证优势 |
| [Bailey等，The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf) | 原始研究；作为进阶回测评估参考 | 本次没有计算PBO，也未对现有策略做统计认证 |
| [Frazzini、Israel、Moskowitz，Trading Costs，2018](https://www.aqr.com/insights/research/working-paper/trading-costs) | 机构实际交易研究；成本与实施条件 | 其成本量级不直接适用于用户账户 |
| [W3C，PROV Model Primer，2013](https://www.w3.org/TR/prov-primer/) | 官方标准说明；来源、生成活动与责任主体的关联 | 本方案不要求实现整个语义网标准 |
| [Martin Fowler，Bitemporal History，2021](https://martinfowler.com/articles/bitemporal-history.html) | 原作者工程方法；发生时间与记录时间 | 本地时间戳不能凭空还原历史可知信息 |

报告中的目录分层、字段组合、工作频率、试点范围和迁移顺序为综合设计建议。引用研究支持其部分原则，不构成对完整系统效果的实证检验。

## 本地检查范围

1. 对`Projects/companies`一级目录和指定子目录存在性做统计：61家公司；研究档案61、技术分析61、催化剂61、历史60、Wiki命名目录60、事件目录20。隐藏配置和资料质量不由该统计判断。
2. 阅读`_system/dossier_schema.md`相关规范及`_system/README.md`，检查档案依赖、发布和路径兼容性。
3. 定向读取`dossier_orchestrator.py`、`fetch_raw_filings.py`、`sync_valuations.py`、`build_site.py`、`kelly_engine.py`、`paper_portfolio.py`相关路径或逻辑。未执行生产流程，未做完整审计。
4. 以TCOM已有Wiki更新史、06/07历史与现行档案、02和9/21技术分析作为具体例子。对其他公司只检查目录结构，未声称全文研究全部61家公司。
5. 本次没有查询实际账户成交或持仓；关于双账本与执行评价均为设计要求，不能理解为已有实盘成绩。

## 仍需在实施中验证

- 真实操作系统、同步软件和发布链对快照/指针方案的兼容性。
- 现有账号侧技能、定时任务与外部消费者的完整路径依赖。
- 所有财务数据口径及旧模型数字的源表勾稽。
- 账户币种、税费、融资、可交易资产及长短资本桶政策。
- 预测问题能否稳定结算，长期与短期策略是否优于适当基准。
- 系统维护时间是否合理，自动化是否真的减少错误而非扩大传播。

这些是实施前或运行中需要解决的具体问题；本次没有用缺失信息推断用户的风险偏好或替用户改变交易规则。
