# AI 投资研究系统

用 Claude 搭的一套个人投资研究流水线：把「看一家公司」这件事拆成固定的分析模块，
每个模块有自己的方法论和产出格式，结论汇总成估值区间和买卖评级，再由每日自动任务
盯着行情和催化剂，提醒哪些判断需要重新做。

> ⚠️ **这不是投资建议。** 仓库里的评级、目标价、仓位建议都是我自己的判断记录，
> 用于复盘"我当时是怎么想的"，不构成对任何人的推荐。数据可能过期或有错。

---

## 一、这套系统在解决什么问题

散户研究公司最大的问题不是不会分析，是**不成体系**：

- 每次分析的角度都不一样，结论没法横向对比
- 看完就忘，三个月后股价动了想不起来当初为什么买
- 新消息来了，不知道该改哪个结论、要不要改评级

所以这套系统的核心不是"让 AI 帮我分析"，而是**把分析固化成有依赖关系的模块，
把结论固化成可被事件触发重算的注册表**。

分析模块之间有明确的先后依赖：

```
企业文化(使命愿景/领导力/治理)  ──┐
                                  ├─→ 财务预测 ──→ 估值分析 ──→ 战略决策
商业模式 ←──反证── 财务分析      ──┘        ↑
                                          股性分析
```

商业模式的判断必须被财务数据反证（说得再好听，报表对不上就是错的）；
财务预测同时依赖企业文化、商业模式和财务分析；估值 = 预测 + 股性。

## 二、目录结构

```
Claude/
├── Projects/
│   ├── companies/            # 研究内容主体，一家公司一个目录
│   │   └── {TICKER} {中文名}/
│   │       ├── 研究档案/      # ★ 核心资产：七个分析模块的成品 md
│   │       ├── {公司} Wiki/   # 一手素材整理（原始 PDF 未入库，见第四节）
│   │       └── *.html        # 研究总结（六维可折叠报告）
│   │
│   ├── _system/             # 数据与脚本层，不放研究内容
│   │   ├── companies.json           # ★ 全库唯一真相源（公司清单 + GICS 分类）
│   │   ├── valuation_registry.json  # ★ 估值真相源（评级 / 买卖区间 / 目标价）
│   │   ├── three_year_valuation_registry.json  # ★ 三年目标价
│   │   ├── position_triggers.json   # ★ 仓位触发规则
│   │   ├── portfolio_registry.md    # 上面几个的可读生成视图
│   │   ├── scripts/                 # 引擎（凯利仓位、数据校验、建站等）
│   │   ├── host_pipeline/           # 宿主机定时任务
│   │   ├── daily_briefing/          # 每日简报（成果）
│   │   ├── position_advice/         # 每日仓位建议（成果）
│   │   ├── scan_log/                # 每日扫描叙事（成果）
│   │   └── market_data/             # 行情快照（可重拉）
│   │
│   └── 基本面分析汇总/         # 跨公司的横向对比
│
├── skills/                  # ★ 分析方法论（16 个 Skill 的导出副本）
├── Artifacts/               # Cowork 交互看板（组合日报、凯利建议）
├── Scheduled/               # 定时任务配置
└── .agents/
```

**丢了要命的只有四类**（加起来不到 1MB + 研究档案）：
`_system` 的四个 `*.json` 真相源、规范文档、`scripts/` 引擎、
以及 `companies/*/研究档案/`。其余的行情、生成视图、归档全都可重建。

详细的 `_system` 导航见 [`Projects/_system/README.md`](Projects/_system/README.md)。

## 三、分析模块（[`skills/`](skills/)）

| 模块 | 回答什么问题 |
|---|---|
| 使命愿景评估 | 这家公司想去哪里、为什么去 |
| 管理层领导力评估 | 说过的话兑现了吗、危机时怎么做的 |
| 公司治理评估 | 股权、薪酬、资本配置、董事会独立性 |
| 商业模式分析 | 卖什么给谁、怎么收钱、护城河在哪 |
| 细致财务分析 | 报表能不能反证上面的故事 |
| 财务预测 | 三情景收入/利润/现金流 |
| 股性分析 | 这只股票历史上被什么驱动、该用什么估值指标 |
| 估值分析 | DCF + 相对估值 → 买卖区间 |
| 战略决策分析 | 管理层真正在下的那一注是什么 |
| 反推 DCF | 当前股价隐含了什么增长预期 |

每家公司跑完一轮产出会先进 `研究档案/_pending/{时间戳}/`，人工确认后才合并进正式档案。
事件驱动的局部刷新（财报、换帅、并购）走另一条更轻的分诊路径，只重算受影响的模块。

**每个模块的完整方法论都在 [`skills/`](skills/) 里**（导出于 2026-08-09）。
Skill 原本存在 Claude 账号侧，这里是导出的副本，可以直接读、也可以装到自己的 Claude 里，
安装方式和注意事项见 [`skills/README.md`](skills/README.md)。

## 四、哪些内容没有入库

| 未入库 | 体积 | 原因 |
|---|---|---|
| `**/*.pdf`、`*.pptx` | ~370MB | 下载的 10-K / 财报 / 演示稿，可从 SEC EDGAR、交易所、公司 IR 免费获取 |
| `raw/`、`公司公告/` 下的 `*.html` | ~110MB | SEC 原始全文，单个文件可达 40MB |
| `Artifacts/*/versions/` | ~46MB | 看板的历史版本快照，重复内容 |
| `Projects/.obsidian/` | ~9MB | 我本机的 Obsidian 配置和插件，对别人无用 |
| `Projects/website_deploy/` | — | 研究网站的部署代码，是**独立的 git 仓库**，单独管理 |

规则见 [`.gitignore`](.gitignore)。所以 clone 下来后，
`Wiki/raw/` 一类目录会是空的或只剩 xlsx，这是预期行为。

## 五、别人想复用的话

这套东西高度个人化，直接拿去用的价值不大，能借鉴的是**方法结构**：

1. 先读 [`skills/README.md`](skills/README.md)——方法论总览和模块调度关系
2. 再看 `Projects/_system/README.md` 理解数据层怎么分（真相源 / 引擎 / 成果 / 可重建）
3. 挑一家公司的 `研究档案/` 通读，看七个模块怎么互相引用、怎么交接
4. 看 `valuation_registry.json` 的结构——评级和买卖区间怎么从分析里落下来
5. 看 `scripts/kelly_engine.py`——情景凯利怎么把估值分歧转成仓位

Skill 正文都在 [`skills/`](skills/) 里，可以直接读。有问题随时问我。
